# arcora-audio

[返回总览](../README.md)

`arcora-audio` 是面向 Haxe、HashLink 和 Arcora 的原生音频运行时，提供游戏声音播放、实时混音、精确调度和空间音频。

## 功能总览

| 功能 | 支持内容 |
| --- | --- |
| 声音播放 | 预加载与流式 PCM、暂停与恢复、播放位置、循环、音量、音高和声像。 |
| 混音与效果 | 多级混音总线、效果链、发送与返回通道、滤波、均衡、压缩、限制和延迟。 |
| 大量声部 | 逻辑与实际混音声部分离，按优先级和预算选择参与混音的声音。 |
| 精确时间 | 以采样帧调度播放及参数变化，提供声音时钟、延迟估计和主机时间换算。 |
| 节奏游戏 | 变速曲目、拍数与时间换算、循环、预滚，以及输入、输出和显示延迟校准。 |
| 空间声音 | 基础 3D 声像与衰减，可选 Steam Audio CPU、HRTF、遮挡、反射和路径传播。 |
| 设备与诊断 | 播放设备选择、设备状态、生命周期暂停恢复、离线渲染，以及延迟和混音负载统计。 |

## 特色功能

- **按采样帧安排声音与节奏**：播放、音量和声像变化可以定位到混音时间线；变速谱面、输入时间及显示延迟也可与音频时钟关联，适合节奏游戏和需要精确同步的交互。
- **大量声音的虚拟化管理**：逻辑声部和实际混音声部分离。系统按优先级、声音类型与预算分配混音资源，未混音的声部继续推进播放位置，适合同时存在大量环境音效的场景。
- **可选几何声学与自适应空间预算**：Steam Audio CPU 可使用场景材质和网格计算遮挡及反射，路径传播还需要已烘焙的 Probe。HRTF 资源不足时可以回退到基础 3D；几何声学需要对应组件和场景数据。
- **实时与离线共享混音处理**：运行时提供总线、DSP、调度与重采样，也支持离线输出，适合在无播放设备时生成或检查音频结果；离线重采样不随宿主速度自动切档。

## 播放、混音与效果

音频可从预加载数据或实时写入的流中播放，适合背景音乐、音效和持续生成的声音。输入支持 Float32、Signed16 以及 1 至 8 个声道，最终混音输出为双声道。预加载声音支持循环和定位；流式循环需要持续提供相应音频数据。流使用有界缓冲，由单一生产者写入，每个流同时最多供一个播放声部消费。

混音总线可以按音乐、环境、语音、音效等用途组织声音，并通过多级总线及发送通道组合效果。内置 DSP 支持增益、声像、低通、高通、参数均衡、压缩、限制和延迟；效果参数可按混音时间渐变。

系统将逻辑播放与实际参与混音的声部分开管理，可以根据声音类型、优先级、增益和保护设置决定哪些声部进入混音。暂时未参与混音的声音仍随时间推进播放位置，适合同时管理大量环境声和游戏音效。

音乐重采样提供高质量、均衡、线性和自适应模式；自适应模式根据回调负载调整质量，普通声音和击打音效使用线性插值。离线渲染不会按照宿主运行速度改变自动重采样质量。

## 时间控制与节奏游戏

音频时间线以采样帧为单位，支持在指定时刻启动、停止或重启声音，并安排音量与声像变化。多个声音的参数也可以批量安排到同一时间点，并可取消尚未执行的事件；对于已错过目标时刻的事件，可以选择拒绝或调整执行时间。空间声音还可根据已知空间处理和总线路径延迟，安排目标可听时间。

音频系统区分源音频、混音和设备的采样时间并进行采样率换算；音频时钟提供输出与重采样延迟、时钟质量，以及混音和设备时间与主机时间的关联。节奏游戏功能在此基础上提供速度变化表、拍数与帧位置换算、谱面与声音时间映射、预滚和循环，同时支持输入、输出与显示延迟校准。设备或时间线发生变化时，节奏时间映射需要重新建立。

## 空间音频

基础 3D 音频根据监听器和声源的位置、方向与距离计算声像和衰减，支持声源锥形范围、距离衰减与空间化混合。Steam Audio CPU 路径可进一步提供 HRTF、直接声、空气吸收、方向性、遮挡、透射、反射、混响和路径传播，也支持独立的湿声总线。外部一阶 Ambisonics 使用四通道 ACN 排列，支持 SN3D 和 N3D 归一化。

空间场景可以包含材质、静态与实例几何体，支持生成、保存和加载 Probe 数据，以及异步烘焙反射和路径传播。空间化按声音启用，遮挡、反射和路径传播需要对应场景资源；路径传播还需要已烘焙的 Probe。

系统可按声部优先级和可用预算分配 HRTF，容量不足时回退到基础 3D；也可为需要稳定处理路线的声部保留配额。可选的自适应空间预算会根据回调负载调整处理频率和配额。HRTF 支持内置数据及受支持的 SOFA 文件，特定直达声配置还可平滑切换 HRTF 或耳机、立体声输出模式。

发行配置分为核心功能配置和 Steam Audio CPU 配置，后者是默认构建配置。Steam Audio 不可用时可回退到基础 3D，也可以配置为必须成功启用；实际空间效果取决于编入的组件和项目设置。

## 底层与平台

混音、时钟、调度、重采样和资源池由音频运行时管理，设备连接使用 miniaudio。音频回调使用预先准备的有界资源，执行混音时不进行动态分配、锁等待或文件与网络 I/O。系统支持流式生产、稳定设备标识、设备状态与队列监控，以及混音阶段的性能统计；事件与指标覆盖设备丢失和恢复、时钟不连续、流缓冲不足、队列溢出、声部抢占和空间化回退。音乐重采样在适用处理器上提供 SSE2 或 NEON 实现。

Arcora 项目可以使用本库的音频后端，也可以使用 OpenAL 后端；两种后端可同时编入应用，实际选择取决于音频配置和构建内容。

| 平台 | 支持范围 |
| --- | --- |
| Windows x64 | WASAPI 播放设备；核心音频和 Steam Audio CPU 路径。 |
| Linux x64 | 提供 null callback 和 ALSA 构建路径；实际声卡接入属于预览范围。 |
| macOS | 提供原生构建入口，设备接入属于预览范围。 |
| Android | 提供 arm64、API 24 及以上的原生构建入口，设备接入属于预览范围。 |
| iOS | 提供 arm64、iOS 12 及以上的原生构建入口，设备接入属于预览范围。 |

平台可用性还取决于原生模块、设备和项目配置。
