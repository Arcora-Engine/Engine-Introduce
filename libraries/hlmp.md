# hlmp

[返回总览](../README.md)

hlmp 是面向 Arcora 和 HashLink 的运行时性能分析库。它采集帧、CPU、GPU、GC、托管堆与线程数据，提供实时视图和离线分析，帮助定位慢帧、内存增长和线程等待。

## 功能总览

| 功能 | 支持的能力 |
| --- | --- |
| 帧与 CPU 分析 | 采集帧时间、FPS、工作区间、函数调用、线程及自定义计数器。 |
| GPU 分析 | 在支持的图形后端采集 GPU 阶段、队列和时间戳数据。 |
| 内存与 GC 分析 | 记录托管对象分配、存活、引用关系和垃圾回收事件。 |
| 等待与调度分析 | 分析锁竞争、等待栈、线程调度、off-CPU 区间和等待环。 |
| 实时视图 | 提供应用内概览、时间线、调用树、火焰图和浏览器视图。 |
| 捕获与离线分析 | 支持手动或条件触发捕获、滚动记录、捕获对比及性能预算报告。 |

## 特色功能

- **关联游戏帧与底层事件**：在相应采集组件启用时，可以在同一分析流程中查看 Arcora 渲染阶段、CPU 工作区间、GPU 队列、GC 和线程等待，帮助定位慢帧出现的位置。
- **保留问题发生前后的上下文**：滚动记录可保存最近一段事件，并由慢帧、GC 停顿或主线程无响应等条件触发捕获；缓冲区和磁盘预算可配置，结果仍需结合事件丢失情况判断。
- **分析托管对象的保留关系**：堆捕获可以查看对象引用、保留路径和支配关系，辅助排查内存增长；覆盖范围取决于运行时和采集配置。

## 可采集的数据

Arcora 集成可以记录 FrameGraph 的 CPU 阶段、GPU pass、提交和临时资源信息；项目也可以标记工作区间、记录自定义计数器和启用函数级插桩。HashLink 的配套性能采集能力可提供虚拟机与原生调用边界、异常、线程、对象分配及 GC 事件。

托管堆分析可展示捕获范围内的对象分配、迁移、存活、引用根与引用边，并分析引用保留路径、支配树和保留字节数；捕获结束时仍存活的对象可作为进一步排查的候选。GPU 分析可观察队列等待、资源生命周期和显存压力；锁竞争、等待栈和线程调度需要对应的运行时钩子或平台数据。GPU 时间戳采集需要已初始化且支持该功能的 D3D12 或 Vulkan 后端。

## 实时视图与捕获

应用内视图提供性能概览、可缩放时间线、调用树和火焰图；MicroProfile Web 通过本机服务展示 CPU、GPU 和计数器数据。时间线支持检索、过滤、查看事件详情及分页读取捕获文件。

捕获支持手动启动，也可由 CPU 或 GPU 帧耗时、GC 停顿或主线程无响应等条件触发。Flight Recorder 可在磁盘预算内滚动保存事件，保留触发前后的上下文。采集范围可以从常驻聚合扩展到详细时间线和深度运行时数据，并可配置内存、磁盘及缓冲区策略；缓冲区溢出和缺失事件会影响分析完整性。

.hlmpraw 捕获文件采用分段、CRC 校验和 LZ4 压缩，支持大文件分页读取与截断恢复。离线工具可以对比捕获、分析大型文件、按性能预算生成 JSON 或 JUnit 报告；启用相应运行时数据后也可整理 ZGC 周期事件。

## 分析范围与平台条件

分析结果可以关联慢帧期间的 CPU、GPU、GC 和等待事件，但事件发生时间重叠本身不足以证明因果关系。托管对象追踪覆盖 HashLink 堆，不代表涵盖第三方原生库自行分配的全部内存；数据丢失、采集起点和时钟校准也会影响结论。Windows 可结合 ETW 分析线程调度，Android 可与系统跟踪数据关联；采集范围与权限取决于平台。

HashLink 底层事件需要带性能钩子的匹配运行库。Windows x64 提供 JIT 和 AOT 组件，线程调度数据通常需要系统权限；Linux 可从源码构建，Android arm64 AOT 可通过 Beap 接入，需要 API 24 及以上和匹配的原生组件。采集开销取决于采集范围、事件量及预算。
