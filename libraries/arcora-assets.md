# arcora-assets

[返回总览](../README.md)

`arcora-assets` 是 Arcora 的资源处理与分发库，覆盖从素材导入、格式转换、资源构建，到打包、运行时加载和远程更新的流程。

## 支持的功能

| 功能 | 支持内容 |
| --- | --- |
| 模型资源 | 导入常用模型格式，处理场景层级、网格、骨骼、动画和材质，生成 Arcora 模型资源。 |
| 纹理与环境 | 导入和转换图像、HDR 纹理及压缩纹理，生成 mipmap 和环境光照数据。 |
| 动画、字体与音频 | 处理动画裁剪、重定向和压缩，以及字体、矢量图和音频编码。 |
| 着色器与材质 | 保存目标后端、编译工具、着色器变体和材质能力需求。 |
| 资源构建 | 根据清单和依赖关系执行资源转换，支持并行构建、缓存和资源分析。 |
| 打包与更新 | 使用 HPAK 打包，使用 HDLT 制作增量更新，支持完整性与签名验证。 |
| 运行时加载 | 支持按需加载、资源预取、按页读取、缓存及 CPU/GPU 预算管理。 |
| 远程分发 | 支持分块下载、断点续传、带宽控制、更新路径规划和版本回滚。 |
| 运行时转换 | 在支持的原生目标中，于应用运行期间转换模型、纹理和动画。 |

## 特色功能

- **面向流送的资源包**：HPAK v2 可以记录纹理 mip、模型 LOD 等资源页，运行时按需读取，并配合 CPU/GPU 预算管理驻留内容。远程按页流送需要服务端支持范围读取，并由数据源提供异步读取。
- **依赖驱动的构建与热重载**：资源构建根据源文件、选项、工具链和依赖判断缓存是否可复用。文件变化后，热重载框架可重建受影响的资源，并在新版本完整准备后发布；文件监听和发布机制需要宿主接入。
- **增量分发与版本恢复**：HDLT 增量包支持从已有 HPAK 重建目标版本，更新规划可考虑下载量、磁盘空间和计算量。配合签名目录与版本管理，可在校验后激活候选版本并保留回滚能力；实际 CDN 服务由项目接入。
- **运行时内容转换**：支持在应用运行期间转换模型、纹理和动画，适合需要在运行中导入内容的工具或游戏；具体格式取决于预先编入的原生后端，移动目标使用 HL/C。

## 模型与场景资源

模型导入支持 glTF/GLB、OBJ/MTL、STL 和 FBX，可以生成 Arcora 使用的 HMD 模型。已有 HMD 也可导出为 GLB。glTF 管线覆盖场景层级、网格、蒙皮、变形目标、相机、灯光、动画、GPU 实例及材质变体；支持稀疏访问器和多种图元，并处理 PBR 材质中的透明度、贴图变换、clearcoat、transmission、sheen 和 iridescence 等属性。

导入过程中可以处理坐标系与单位、生成法线和切线，优化顶点缓存、顶点读取和过度绘制，并通过网格简化准备 LOD 和 meshlet。OBJ、STL 文件缺少完整坐标系与单位信息时，需要由项目指定。Draco、meshopt 和 meshlet 等能力依赖匹配的原生组件；FBX 导入需要单独准备 Autodesk FBX SDK。模型中保存的材质属性能否显示，还取决于目标渲染器。

## 纹理、动画与其他素材

纹理管线支持 PNG、TGA、JPEG、Radiance HDR、OpenEXR 和部分未压缩 TIFF，以及 DDS、KTX、KTX2 和 Basis 等压缩纹理容器。运行时可处理 RGBA 及 BC1–BC7、ETC2/EAC RGBA8、ASTC LDR 4×4、PVRTC1 RGBA 4 bpp 等 GPU 原生压缩纹理，覆盖二维、数组、立方体和立方体数组及其 mip 数据；Basis 转码目标可根据设备能力选择。转换流程可按颜色、法线、透明边缘和 HDR 等用途生成 mipmap，也能处理立方体贴图接缝。IBL 工具可根据环境贴图生成漫反射、镜面反射和 sheen 所需的数据。具体容器支持、压缩或解码能力取决于所选后端。JPEG、OpenEXR、纹理压缩与部分转码路径需要相应原生组件。

动画管线支持 `.anim`、ACL 和 ACLDB，以及片段裁剪、曲线优化、按映射重定向与叠加动画制作；ACL 编解码需要原生后端。位图字体可转换为 BFNT；SVG 可通过配置的外部工具转换为位图、网格或运行时矢量产物。已弃用的作者工具兼容路径还可生成 SVG 的 MSDF PNG，但不作为正式发布产物的来源。

音频转换可调用外部 FFmpeg 生成 WAV、FLAC、MP3、OGG、Opus、AAC 和 ALAC，实际格式取决于工具包含的编码器。音频产物元数据可记录声道、时长、循环点、响度、定位表和流式分页信息。音游作者工具的兼容路径可通过 FFmpeg 分析规范化音频，生成波形、首尾静音、谱面偏移及 PCM 内容标识。该旧作者工具不作为正式发布产物来源；正式资源构建使用受控外部工具。字体产物还可记录字形、字距、Unicode 范围与后备字体。

## 构建、缓存与资源包

资源清单描述源文件、输出格式、目标平台、标签、资源组及构建选项。构建系统根据依赖关系组织任务，在支持多线程的目标上并行处理互不依赖的资源，并可限制 CPU、文件 I/O、图像预计算和内存预算。构建缓存根据源内容、转换选项、工具链和目标配置判断产物是否可复用。

资源工具还支持构建计划、依赖检查、资源分组和体积统计、目标能力检查、缓存管理及导入报告。外部工具产物可以记录工具与依赖身份、检查结果并参与缓存；操作系统级沙箱需要由构建环境提供。远程缓存与分布式构建提供接入能力，传输和服务端需要项目自行提供。

资源热重载框架可接收文件变化，按依赖重建受影响的资源，并在完整新版本准备成功后发布；具体文件监听和发布机制需要宿主接入。着色器与材质产物还可记录目标后端、编译器、变体和设备能力，构建时检查材质需求与着色器是否匹配。

HPAK v2 将资源组织为支持按文件区间和页读取的资源包，可随应用安装，也可通过支持 HTTP Range 的服务分发。应用可组合普通文件与多个资源包，并为资源包设置优先级。

## 运行时加载与流送

运行时可按资源标识、虚拟路径或标签查找资源，并预取依赖。相同资源的加载请求可以合并，同时支持并发读取、取消、超时和重试。纹理 mip、模型 LOD 等数据可按页读取，并按由粗到细的依赖关系逐步加载；按页流送需要资源包或数据源提供实际的异步范围读取能力。

内存管理支持 CPU 与 GPU 分别设置预算，并按最近使用情况回收不再使用的资源。GPU 预算统计已上传和等待释放完成的资源，在显卡工作完成后扣减实际驻留；设备重建时，可利用保留的数据恢复资源。显存预算查询依赖所选图形后端，不支持查询的后端使用估算信息。

## 远程更新与内容保护

远程分发支持分块下载、已下载区间校验、断点续传，以及前台、预取和后台请求调度。项目可以限制连接数与带宽；服务端需要支持范围读取。内置下载默认使用 HTTPS，不跟随重定向，可信开发环境可显式允许 HTTP；单个包默认上限为 1 GiB，可由项目调整。

HDLT 增量包记录从旧 HPAK 重建目标 HPAK 所需的差异。更新过程可综合下载量、临时磁盘空间和计算量选择更新路径，核对基础包、增量包和目标包后激活候选版本，并保留回滚能力。签名目录支持最低客户端版本、灰度条件及撤销信息。

HPAK 和 HDLT 支持完整性与签名验证；加密包要求签名，认证加密和密钥管理由项目提供。资源路径仍可能从包中获知，发行系统需要管理可信密钥、撤销状态和可恢复版本。

## 应用内转换与平台范围

运行时转换支持模型、纹理和动画的同步或异步处理，可限制输入、输出、缓存和并发规模。外部依赖的读取受范围限制，路径穿越和远程 URI 等输入会被拒绝。转换使用构建时确定的原生组件；实际格式能力取决于应用编入的后端。

当前主要发布目标是 Windows x64 和 HashLink。Linux、macOS、Android、iOS、Web 及其他语言目标的功能处于兼容或实验范围，取决于工具链、原生组件和设备。运行时转换面向 HashLink JIT 与 HL/C，Android 和 iOS 使用 HL/C。
