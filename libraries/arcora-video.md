# arcora-video

[返回总览](../README.md)

`arcora-video` 为 Arcora 提供平台视频解码、画面播放与外部时钟同步，可将视频显示在 2D 场景中，也支持将解码画面交给图形设备处理。

## 功能总览

| 功能 | 支持内容 |
| --- | --- |
| 视频播放 | 加载、暂停、恢复、定位、循环，以及就绪、结束、片源变化和错误通知。 |
| 时间同步 | 单调时钟、手动时钟、音频时钟接入，按外部时间线选择画面。 |
| 解码与缓冲 | 平台原生解码、软硬件解码选择、有界帧队列和后台解码。 |
| 画质与片源 | 多种画质策略、不同分辨率片源，以及满足条件时的动态片源切换。 |
| 颜色与画面 | NV12、P010、RGBA8，颜色范围与色域信息、裁剪、旋转、像素宽高比及 HDR 到 SDR 的色调映射。 |
| 图形传输 | CPU 帧传输，以及 D3D11、D3D12、Vulkan、VideoToolbox 和 MediaCodec 外部画面接入。 |
| 运行诊断 | 帧解码、呈现、丢弃、延迟、队列水位、定位、循环和设备恢复统计。 |

## 特色功能

- **由外部时间线驱动画面**：视频按照游戏时钟或音频时钟选择画面，延迟时丢弃过期帧，适合需要与游戏事件或另行播放的音轨同步的场景。
- **画质与片源可随负载调整**：支持轻量线性采样、高质量重建，以及根据持续负载调整质量。不同分辨率片源的内容、时间线、色彩、位深和静态 HDR 元数据需要一致，且版本须受当前环境支持；原生异步切换目前限于 CPU 帧传输路径。
- **接入平台解码与 GPU 画面**：使用各平台媒体后端，并在设备和图形后端满足条件时导入外部 GPU 画面；CPU 传输可作为相应配置下的回退。硬件解码与外部画面可用性需要分别确认。
- **保留视频色彩信息**：支持 NV12、P010 和 RGBA8，记录颜色、裁剪与旋转等信息，并提供 HDR 到 SDR 的色调映射。常规 2D 视频对象输出 SDR；色调映射仍需颜色与设备认证，完整 HDR 显示尚未认证。

## 播放与时间同步

视频播放支持定位、暂停、恢复和循环，可与游戏时间或音频时钟关联。播放器根据主时钟及可配置的视频偏移选择应当显示的最新画面，并丢弃已经过时的画面；解码和画面更新分别运行，帧数和内存使用可以设置预算。项目也可以接入自定义解码器，处理其他来源的视频画面。

视频库负责画面。容器中的音轨需要由应用另行播放，并与视频使用的时间线同步。

项目可准备内容和时间线一致的多个不同分辨率片源，并结合显示尺寸和画面负载选择。画质策略覆盖线性采样、随持续负载调整，以及在受支持路径内保留源精度并使用 Catmull-Rom 高质量重建；高质量模式遇到过载时报告限制。原生异步片源切换适用于实际采用 CPU 帧传输的流；外部 GPU 画面路径保留当前片源。

## 格式、颜色与画质

基础片源范围为本地 MP4、H.264、8 位 4:2:0 SDR。其他容器、编码、硬件解码和 HDR 能力取决于系统、设备与图形接入。

解码画面支持 NV12、P010 和 RGBA8。P010 路径可保留 10 位数据；画面信息可包含 BT.601、BT.709、BT.2020 颜色矩阵、完整或有限范围、SDR/PQ/HLG 传递函数、色域、亮度、色度位置、裁剪、旋转和像素宽高比。常规 2D 视频对象输出 SDR，HDR 视频需要启用 HDR 到 SDR 的色调映射；最终显示效果取决于处理和显示链。

## CPU 与 GPU 画面传输

视频画面可以通过 CPU 内存传输，也可以在平台和设备支持时导入外部 GPU 画面。外部画面接入覆盖 Direct3D 11、Direct3D 12、Vulkan、VideoToolbox 和 MediaCodec；硬件解码与 GPU 画面导入是分别判断的能力，实际路径仍可能发生 GPU 拷贝。

Windows 的 Vulkan RHI 呈现路径可导入符合设备条件的偶数尺寸 NV12 外部画面，供图形采样；该路径需要共享图像、timeline semaphore、synchronization2 及 R8/RG8 线性采样能力，P010 和 HDR 不在当前入口范围。常规 2D 视频对象使用 Vulkan 时采用 CPU 传输；Linux 的 GPU 视频画面导入尚未作为可用路径发布。原生视频着色器可将符合条件的外部 NV12 画面转换为线性 RGBA16F，交给后续画面合成；当前转换范围限定为 BT.709、有限范围、SDR、8 位和受支持的色度位置。

解码帧队列和画面资源有容量预算；设备丢失时可按配置重新创建相关资源并恢复播放。GPU 画面会依据实际图形工作完成情况回收，避免播放设备或图形设备仍在使用时提前释放。运行时分别报告编入的硬件能力、当前设备能力与具体视频流实际使用的解码和传输方式。

## 平台与媒体后端

| 平台 | 媒体后端及条件 |
| --- | --- |
| Windows | Media Foundation；发布目标为 Windows 10 22H2 及以上。 |
| macOS / iOS | AVFoundation 与 VideoToolbox；要求 macOS 12 或 iOS 15 及以上。 |
| Android | MediaExtractor 与 MediaCodec；要求 Android 10 / API 29 及以上。 |
| Linux | glibc 2.31 及以上、GStreamer core、app、video 1.18 及以上；需要部署受控插件目录。 |
| 浏览器 | 使用 HTML 视频元素；跨源画面读取需要服务器允许。 |

Linux 媒体后端使用受控 GStreamer 插件目录，不加载 `gst-libav`；进程中其他组件提前初始化 GStreamer 会影响该后端的启用。浏览器路径使用静音视频画面跟随外部时钟；虽然可以查询 WebCodecs 能力，当前浏览器播放路径使用 HTML 视频。
