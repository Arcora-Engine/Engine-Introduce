# arcora-mobile

[返回总览](../README.md)

`arcora-mobile` 为 Haxe/HashLink 应用提供 Android 和 iOS 系统服务接入，让游戏和工具使用设备信息、权限、触感、分享及其他移动平台能力。

## 支持的功能

| 功能 | 支持内容 |
| --- | --- |
| 设备信息 | 读取厂商、型号、系统和应用版本、语言地区与设备类别。 |
| 权限 | 查询和请求相机、麦克风、相册、使用期间的位置及通知权限。 |
| 触感与振动 | 提供轻、中、重触感，以及成功、警告、错误等反馈。 |
| 界面与系统交互 | 读取安全区，使用文本剪贴板，打开链接、Deep Link 和应用设置页。 |
| 分享与存储 | 调用系统分享文字或 URL，保存普通的轻量字符串设置。 |
| Android 性能 | 支持性能提示、温控状态、游戏模式和游戏状态。 |
| 桌面开发 | 提供可配置的模拟后端，用于检查移动功能的业务流程。 |

## 特色功能

- **游戏工作负载的 Android 性能提示**：可以结合 Arcora 任务系统，将工作线程的目标与实际耗时提供给 Android 性能提示服务，同时读取温控与游戏模式信息。Android 12 及以上且设备服务可用时可以创建性能提示会话，具体调度由系统决定。
- **移动系统状态统一接入**：相机、麦克风、相册、位置和通知等权限会区分授权、拒绝、受限制与不可用等状态，并配合安全区、触感、剪贴板、分享和链接等系统能力使用。
- **桌面模拟与自定义宿主**：开发时可以在桌面预设权限和能力结果，并记录分享、链接及触感请求；移动应用也可由自定义宿主提供平台实现。桌面模拟需要显式使用模拟后端。

## 设备、权限与系统配置

设备信息包括厂商、型号、系统与应用版本、语言地区和设备类别，不采集广告 ID 或硬件序列号。权限覆盖相机、麦克风、相册、使用期间的位置和通知，并区分未决定、请求中、已授权、拒绝、永久拒绝、受限制和不可用等状态。权限请求可能异步完成。

Android 应用需要在 manifest 声明实际使用的权限；Android 13 起图片读取和通知使用各自的权限，较早版本相册读取使用旧存储读取权限，通知按已授权处理。iOS 需要在 `Info.plist` 提供相机、麦克风、相册和位置的用途说明。

## 触感、安全区与分享

触感支持轻、中、重反馈，以及成功、警告和错误反馈，也可请求振动。iOS 的振动时长由系统决定，应用提供的时长作为提示。安全区提供四边 inset，Android 使用 dp，iOS 使用 point，可用于避开刘海、圆角和系统区域。

系统交互包括文本剪贴板、URL、Deep Link 和应用设置页。分享支持文字、URL、标题与主题；系统接受打开或分享请求，表示相关系统操作已发起。Android 11 及以上查询自定义 scheme 需要在 manifest 声明 `<queries>`，iOS 需要配置 `LSApplicationQueriesSchemes`。

轻量存储提供字符串读取、保存、删除和清空，适合普通偏好设置；密钥和密码需要使用平台安全存储。

## Android 性能与游戏状态

Android 接入 Dynamic Performance Framework（ADPF），支持根据目标工作时长和实际工作时长向系统提供性能提示，并可结合 Arcora 的任务系统管理工作线程。库也提供温控状态、温控余量、游戏模式和游戏状态查询或上报。性能提示由 Android 决定如何使用，不保证固定 CPU 核心或自动改变帧率。

| 能力 | 最低 Android 版本 |
| --- | --- |
| 温控状态 | Android 10 / API 29 |
| 温控余量 | Android 11 / API 30 |
| 性能提示会话、游戏模式 | Android 12 / API 31 |
| 游戏状态 | Android 13 / API 33 |
| 更新会话线程 | Android 14 / API 34 |
| 会话节能偏好 | Android 15 / API 35 |

游戏模式和游戏状态要求应用声明游戏类别。温控余量可按需预测未来 0 至 60 秒，采样间隔至少为 10 秒；系统没有有效数据时会报告不可用。应用进入后台或 Activity 销毁时性能提示会话结束，回到前台后需要重新建立。iOS 和桌面默认实现不提供这组 Android 专属服务。

## 平台实现与构建

Android 使用 Kotlin 系统服务与 SDL3、JNI 和 HashLink 桥接；iOS 使用 UIKit、AVFoundation、Photos、CoreLocation、UserNotifications 和 AudioToolbox 等系统框架。平台接入包含对应的生命周期和权限处理，并可用于自定义宿主。

Android 和 iOS 原生应用可通过 Beap 的 LLVM AOT 构建接入；Android 还需要 AAR 与 Kotlin 运行库。移动服务也可组合自定义宿主提供的实现。桌面默认不提供移动系统服务；模拟后端可预设能力和权限结果，并记录分享、链接、触感及权限请求，便于开发期间验证业务流程。
